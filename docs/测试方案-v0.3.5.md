# v0.3.5 自动化测试方案与上线标准

## 1. 分层

| 层 | 目的 | 运行位置 | 触发 |
| --- | --- | --- | --- |
| L0 静态 | PowerShell 语法、UTF-8 BOM、BAT/VBS CRLF、发布包文件清单 | GitHub Windows Runner | 每次推送/PR |
| L1 单元 | 配置 TOML、进程隔离、商店查找兜底、磁盘预检、启动器复用 | GitHub Windows Runner | 每次推送/PR |
| L2 入口 | BAT→bootstrap→安装器链路，带空格/中文/`&`/`!` 路径，失败日志保留 | GitHub Windows Runner | 每次推送/PR |
| L3 真实安装包 | 对真实 `app.asar` 执行组件对照、补丁、分块哈希、未改动资源校验 | `E2E Windows` 工作流第一步，或本地 | 每个新 Codex 版本 |
| L3.5 真实端到端 | 安装官方 MSIX → 运行真实安装器 → 启动中文副本 → 通过 DevTools 协议读取界面语言并截图 → 官方程序对照 → 恢复英文 | `E2E Windows` 工作流（windows-2022、windows-2025） | 每个新 Codex 版本、每次发布前 |
| L4 实机 | 复制、启动、重复启动、界面中文、恢复英文 | Windows 10 22H2 与 Windows 11 24H2 实机/虚拟机 | 每次发布前 |

## 2. 用例清单

| 编号 | 用例 | 命令 |
| --- | --- | --- |
| T1 | 配置、备份、进程边界 | `tests\test-regressions.ps1` |
| T2 | 无按键安装入口 | `tests\test-unattended.ps1` |
| T3 | 入口与错误日志 | `tests\test-bootstrap.ps1 -HeadlessRunner` |
| T4 | 复制失败与清理 | `tests\test-copy-failures.ps1` |
| T5 | 自定义安装识别 | `tests\test-discovery.ps1` |
| T6 | 商店查找兜底、磁盘预检 | `tests\test-store-fallback.ps1` |
| T7 | 启动器复用与失败传播 | `tests\test-launcher.ps1` |
| T8 | 真实组件对照与补丁完整性 | `python tests\test-locale-gate.py <app.asar>` |
| T9 | 官方中文资源审计 | `node scripts\analyze-codex-asar.mjs <app.asar>` |
| T10 | 发布包内容 | `scripts\package-release.ps1` 后 `tests\test-release.ps1`（中文代码页） |

新 Codex 版本发布时，维护者把 MSIX 地址写入仓库变量 `CODEX_MSIX_URL`（或运行时输入），手动运行 `E2E Windows` 工作流。产物中的 `zh-copy.png`、`zh-copy.json`（`lang`、中文字符数）是界面已汉化的直接证据。T8 失败说明官方加载逻辑结构变化，必须人工审查后才能放宽规则，不能直接改正则让其通过。

## 3. 实机验收矩阵（L4）

| 环境 | 安装方式 | 必查项 |
| --- | --- | --- |
| Win10 22H2（19045），中文系统 | 商店版 | 一键安装无按键完成；“Codex 中文版”打开后菜单和主界面为中文 |
| Win10 22H2，英文系统 + 中文用户名 | 商店版 | 路径含中文时复制和快捷方式正常 |
| Win11 24H2，中文系统 | 商店版 | 同上；官方图标仍打开官方程序 |
| Win11，企业策略禁用 Appx 模块 | 商店版 | 注册表兜底找到安装位置 |
| 任一系统，剩余空间 < 3 GB | 商店版 | 复制前提示磁盘不足，未留下副本 |
| 任一系统 | 已汉化后 Codex 升级 | “检查状态”提示副本过期；重新安装后生效 |
| 任一系统 | 恢复英文 | 语言恢复、插件原文恢复、快捷方式删除、对话保留 |

每项保存“检查状态”生成的 `diagnostics\*.json` 和界面截图。

## 4. 上线标准

1. L0–L2 在 GitHub Actions 全部通过，附运行链接。
2. 当前 Store 最新版的 L3 通过（T8 输出四行 PASS）。
3. L4 至少完成 Win10 与 Win11 商店版两行，界面中文有截图。
4. 发布 ZIP 的 SHA-256 写入更新说明。
5. 更新说明按“问题原因、修改内容、测试结果、仍未验证的范围”书写，未完成的 L4 项必须列出。

## 5. Windows 自动化测试方案比较

| 方案 | 系统 | 优点 | 局限 | 结论 |
| --- | --- | --- | --- | --- |
| GitHub 托管运行器 `windows-2022` / `windows-2025` | Server 2022（构建 20348）/ Server 2025（构建 26100），分别对应 Win10 / Win11 同代内核 | 免费、每次干净、有桌面会话、可安装 MSIX、可跑 GUI | 不是客户端版本，没有中文系统语言 | **主方案**，已接入 CI 与 E2E |
| [dockur/windows](https://github.com/dockur/windows)（KVM 中运行 Windows 10/11 客户端，支持无人值守安装和 OEM 脚本） | 真实 Win10 / Win11 客户端，可选中文 | 最接近用户环境；可在带 KVM 的 Linux 主机或自托管运行器上跑 | 每次需下载系统镜像（数 GB，20–40 分钟），需要约 64 GB 磁盘和嵌套虚拟化 | **补充方案**，发布前跑一次中文 Win10/Win11 |
| 自托管运行器（家中/公司的 Win10、Win11 实机或 Hyper-V 虚拟机 + 快照） | 真实客户端 | 可固定中文系统、中文用户名、真实商店环境；快照可还原 | 需要自己维护机器 | 长期推荐，用于 L4 |
| Windows 沙盒（Windows Sandbox，`.wsb` 配置启动脚本） | 与宿主相同的 Win10/11 Pro/企业版 | 本机一次性环境，关闭即清空 | 仅 Pro/企业版；不能装商店依赖较多的包时要注意 | 维护者本地快速复测 |
| Azure 虚拟机（Windows 10/11 镜像）+ 自托管运行器 | 真实客户端 | 可按需创建/销毁 | 需要云账号与费用 | 团队规模扩大后考虑 |

界面语言的自动判定统一使用 `tests/e2e/cdp-check.mjs`：通过 `--remote-debugging-port` 连接窗口，读取 `<html lang>` 和可见文字中的中文字符数，并截图。这比 OCR 或像素对比更稳定，也不依赖系统语言。
