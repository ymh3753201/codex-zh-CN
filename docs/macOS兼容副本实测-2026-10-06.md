# macOS 兼容副本验证记录（2026-10-06）

版本：0.2.0-preview.1。审查起点：517e678。状态：开发预览，未正式发布。

## 问题原因

只写入中文语言设置不能保证主界面加载中文。真实程序的主界面翻译读取远程 enable_i18n 开关，默认关闭；设置页面对应默认值却是开启，所以可以选中文但页面仍英文。

上一个版本只检测和报告这个缺口，没有提供 macOS 兼容副本。不能将这种失败自动认定为「工具正常、只怪官方」。

## 修改内容

- 首次默认只用官方设置。只有本版本官方界面确认仍英文后再次安装，或明确选择兼容汉化，才在工具管理目录创建独立副本；不修改官方 App。
- 保持 ASAR 资源偏移与长度，更新受影响资源的完整和分块 SHA-256。
- 同步 Info.plist 与新版 Electron 框架内的 ASAR 校验值，**不关闭完整性验证**。
- Electron 框架、关联子程序和顶层副本使用本地签名，保留 Hardened Runtime；不冒用 OpenAI 的团队、共享钥匙串、应用组或推送权限。仅副本需要不同签名库的应用内加载权限，系统保护不变。
- 复制前检查空间，逐文件比较完整副本，首次写入前和签名前校验所有物理路径不得越界。写入函数自身也绑定来源文件和独立目标。签名与资源复核后才保存准备记录。准备完成仍不是已启动；启动失败或信号中断另作失效标记，不能再次当作有效目标。
- 不自动重启；失败或中断的副本、旧副本及旧备份保留。配置与启动记录修改前备份，官方升级后旧状态失效。
- 报告分开记录资源、准备、启动和本次界面确认，不能将脚本成功、进程存在或截图存在当成界面验收。
- 官方中文已经正常时，默认不创建副本；--mode native 可强制官方模式。恢复英文并请求重启时先退出受管副本，再打开官方版本，不用名称批量杀进程。

另有开发专用代码探针，执行从真实 ASAR 中取出的语言组件：原程序在远程开关 false 时不加载词条，true 时加载；副本在 false 与 true 时均能加载。这是加载机制证据，**不是完整界面验收**。命令如下，仅供隔离开发环境：

~~~bash
node tests/test-macos-renderer-gate.mjs /path/to/official/app.asar
node tests/test-macos-renderer-gate.mjs /path/to/copy/app.asar --expect-local-copy
~~~

初次启动暴露了两处只靠脚本检查发现不了的问题：新版框架的内嵌校验值也需要更新；页面子程序也需要与修改后的框架采用一致的本地签名。它们均已纳入修复。不能把短暂出现的进程报告为汉化成功。

## 本机保护与测试清理

用户随后要求不再在本机安装测试。已停止全部独立测试进程，将本次隔离应用副本、临时数据及崩溃报告移至废纸篓，可恢复。官方应用主进程保持运行。官方 ASAR、Info.plist 和正式 config.toml 的前后复核校验值一致，没有覆盖对话或正式配置。

后续安装回归、签名夹具和工具包测试只在 GitHub 的一次性测试机器执行；本机只进行源码修改、静态检查和打包，不再启动或安装汉化副本。

## 资料依据

ASAR 的两层完整性检查依据 [Electron 官方说明](https://www.electronjs.org/docs/latest/tutorial/asar-integrity) 和 [Electron 框架源码](https://github.com/electron/electron/blob/main/shell/common/asar/integrity_digest.mm)。本地签名与正式分发签名不是一回事，见 [Apple 分发签名说明](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac)。本工具包只含脚本，不分发修改后的官方 App。
