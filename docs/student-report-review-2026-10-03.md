# 学员安装报告分析（2026-10-03）

结论：这份文字报告没有显示安装失败，描述的是“安装准备完成、界面待确认”。它是实际 Windows 10 场景的新反馈，但不是完整的界面验收记录。本次不扩大补丁匹配规则，不把 26.928 加入已经验证的版本清单。

## 问题原因

- 学员下载默认 main 分支得到 v0.3.4，符合教程“不使用待验收分支”的要求。v0.3.5 仍在草稿更新请求中，仓库没有正式 Release 下载包，不是学员下载操作错误。
- 报告里的 `ready: true` 只能说明找到了完整中文资源。源代码中这个字段不检查中文副本、语言配置或当前窗口，因此不能直接表示“汉化成功”。
- `uiLanguageVerified: false` 代表工具未验证窗口语言，并不代表检测到英文。学员使用 `-NoRestart` 保留当前窗口是正确做法，还需保存任务后手动打开中文版。
- Store `26.928.1915.0`、可执行文件元数据 `154.0.8037.57`、“关于” `26.928.20755` 来自不同信息源。仅凭差异不能认定安装错误。由于没有真实安装包，不能确定 154 编号具体属于哪个运行时组件。
- 旧快捷方式被更新、旧副本保留属于预期行为。报告未提供该次修复前后的原始记录，不能进一步认定失效快捷方式由哪次安装产生。
- “仍是英文就运行修复启动”建议范围过宽。旧修复入口没有校验副本来源和补丁完整性，可对过期或损坏副本再次写入活动记录，随后仍报告成功。旧状态只检查启动器是否存在，也可能漏掉过期或损坏的启动器内容。
- “官方更新后界面会回到英文”并非必然：中文副本是独立副本，可能继续运行旧版本。应核对版本并重新汉化，不能以是否出现英文判断是否已经升级。

## 修改内容

1. 保留旧 `ready` 字段兼容性，新增 `resourcesReady` 和 `readyMeaning` 解释其含义；使用现有 `localizationReady` 判断安装准备。
2. 状态报告增加当前工具版本、副本工具版本、人工验收状态及 `nextAction` 操作建议。安装记录也保存工具版本。
3. 状态检查对持久启动器做源码哈希对照，文件存在但内容不同也会提示修复启动入口。
4. 修复启动前校验官方来源是否变化、中文副本补丁和可执行文件哈希是否有效。失败时停止，保留原记录、旧副本和备份。
5. 安装完成和进程启动提示改为“安装准备完成，界面中文仍待确认”；`-NoRestart` 明确显示第 5 阶段已跳过启动，保留当前任务。
6. 澄清版本编号标签，并补充 AI 安装、反馈和正确排查路径。

## 测试结果

新增回归覆盖：资源齐备但未安装时不能认定就绪；准备成功时仍保持人工验收待确认；官方同路径升级和副本损坏均不能通过“修复启动”重新发布；旧启动器内容变化要提示修复；不自动重启时明确完成五阶段说明。

本次 Windows PowerShell 5.1、真实 robocopy、中文路径、旧式长路径与发布 ZIP 回归结果，以草稿更新请求对应最终提交的 [CI 检查](https://github.com/ymh3753201/codex-zh-CN/pull/3/checks)为准。用例使用合成程序资源，不等于 26.928 真实程序的启动或视觉验收。

## 仍未验证的范围

- 学员报告中的字节替换、资源与分块哈希、官方文件未变化等，均来自用户提供的文字，未取得原始日志、JSON 或安装包独立核验。
- Windows 10 上 Store 26.928 的中文副本实际启动、主要界面、插件界面、重复启动和恢复英文。
- v0.3.5 在 Windows 10/11 实机上的最终表现；v0.3.4 的反馈不能替代升级后验证。
- 该报告中的 2.10 GB、3596 个文件、复制失败 0 等不构成完整运行测试。

## 请学员补充的最少证据

1. 保存当前任务，退出官方窗口后从“Codex 中文版”打开；确认菜单、侧栏和设置是否中文。
2. 提供“检查状态”最新 JSON 和关于窗口截图，先隐藏用户名、密钥与私人内容。
3. 若无法启动，提供上次启动记录；若启动正常但部分英文，提供该位置截图，区分未翻译词条与整个主界面未加载中文。
4. 只有入口失败才修复启动器；状态显示副本过期或损坏时按提示重新安装，不反复修复快捷方式。
