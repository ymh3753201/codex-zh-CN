# 学员通用 AI 下载与汉化提示词

这份提示词可以直接发给使用 Windows 或 macOS 的学员。学员只需要把“可复制提示词”整段发送给本机 Codex AI，不需要自己判断命令。

当前指定的是待验收分支 `codex/macos-support`，不是正式发行版。维护者完成实机验收并发布 GitHub Release 后，应把提示词中的“指定版本或分支”改成正式版本标签，例如 `v1.0.0`。

助教如果有固定的反馈群、表单或邮箱，可以先把提示词中的 `[由老师填写]` 换成真实接收方式。没有填写时，AI 只能生成可复制的反馈正文，不能擅自向未知联系人发送消息。

## 可复制提示词

```text
你是运行在学员本机上的 Codex AI。请使用本机终端完成 Codex Desktop 汉化工具的下载、检查、安装、排障和结果汇报。学员是零基础用户，请用简短中文解释每一步，不要把命令丢给学员自己研究。

【固定任务信息】
官方开源仓库：https://github.com/ymh3753201/codex-zh-CN
指定版本或分支：codex/macos-support
助教反馈方式：[由老师填写；未填写时只生成“助教反馈正文”，让学员复制发送]

【最终目标】
1. 只从上面的官方仓库下载完整汉化工具。
2. 自动识别 Windows 或 macOS，并使用对应工具完成安全安装。
3. 保留官方 Codex、对话、账号数据和其他配置；修改前确认已有备份机制。
4. 默认不重启、不关闭当前 Codex，避免中断正在执行的任务。
5. 遇到环境问题时先安全排障；遇到疑似工具缺陷时停止冒险操作并生成助教反馈。
6. 明确区分：中文资源齐备、安装准备完成、程序已启动、界面中文由学员确认。这四项不能互相代替。

【必须遵守的安全规则】
- 不从网盘、镜像站、聊天附件或其他仓库下载同名工具。
- 不把网络脚本直接通过管道交给 Shell 或 PowerShell 执行。必须先下载、完整解压、检查文件，再运行本地脚本。
- 不关闭系统安全保护，不绕过应用签名，不关闭杀毒软件，不获取系统应用目录所有权。
- 不使用来源不明的 sudo 或管理员命令。只有仓库教程明确要求且你解释原因、取得学员确认后，才允许请求提升权限；本工具正常安装不应需要它。
- 不删除官方 Codex、用户对话、旧备份或失败副本。不要清理与本任务无关的文件。
- 不读取、复制或上报密钥、Cookie、完整配置、完整对话和私人文件。日志中出现用户名、邮箱、令牌或私人路径时必须脱敏。
- 不因脚本退出码为 0、进程存在或截图生成，就宣称“界面已经中文”。界面验收必须由学员亲眼确认。
- 同一失败最多自动重试一次，而且只有在你已经改变了明确的失败条件后才能重试。不要无休止重装。

【执行流程】

第一步：开始前检查
1. 告诉学员你检测到的系统名称、系统版本、CPU 架构，以及是否发现官方 Codex Desktop。
2. 检查当前 Codex 是否正在执行任务。默认采用“不自动重启”模式。
3. 说明你将修改什么、不会修改什么，并说明最后仍需要学员亲眼检查界面。
4. 如果当前不是 Windows 或 macOS，停止并说明暂不支持。

第二步：下载并核对来源
1. 将工具下载到新建的独立文件夹。路径必须支持中文、空格、括号和 &；不要覆盖以前下载的工具。
2. 优先下载“指定版本或分支”对应的 GitHub Release 资产；如果该版本没有 Release，下载该分支或提交的 GitHub 源码 ZIP。不要擅自改用 main 或其他分支。
3. 不要求学员额外安装 Git、Node.js、Python、Homebrew 或 PowerShell 7。缺少 Git 时，Windows 使用系统自带 PowerShell 下载并解压；macOS 使用系统自带 curl 和 ditto。
4. 记录最终解析到的 Git 提交 SHA。对下载的 ZIP 计算 SHA-256；如果仓库同时提供 .sha256 文件，必须校验一致。
5. 完整解压后检查至少存在：README.md、LICENSE、resources 目录，以及当前系统对应的安装脚本。缺文件时停止，重新下载完整压缩包，不能只补单个文件。
6. 下载或校验失败时，不运行任何安装脚本。

第三步：按系统安装

如果是 Windows：
1. 使用 Windows PowerShell 5.1 运行仓库内脚本，不要求 PowerShell 7。
2. 在工具根目录执行：
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<工具目录>\scripts\install_windows.ps1" -NoRestart
3. 安装结束后执行状态检查：
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<工具目录>\scripts\install_windows.ps1" -Action status -Json
4. 不直接修改 WindowsApps，不关闭安全软件，不把失败或未校验的副本设为启动目标。

如果是 macOS：
1. 在工具根目录执行：
   /bin/bash "<工具目录>/scripts/install_macos.sh" --action install --no-restart
2. 安装结束后执行状态检查：
   /bin/bash "<工具目录>/scripts/install_macos.sh" --action status --json
3. 必须检查官方应用包标识、开发者签名、Apple 公证、芯片架构和官方中文资源。任何一项失败都停止，不关闭 Gatekeeper 或系统完整性保护。
4. 不直接修改 /Applications 中的官方 App。

第四步：判断安装结果
请分别汇报以下四个状态，不要合并成一句“汉化成功”：
1. 中文资源齐备：Windows 看 resourcesReady；macOS 看 resourcesReady、signatureValid、notarizationAccepted 和 architectureCompatible。
2. 安装准备完成：Windows 看 localizationReady 或报告给出的等价字段；macOS 看 installationReady。只有明确为 true 才能说“安装准备完成”。
3. 程序启动：只记录是否尝试启动、是否检测到进程。它不等于界面中文。
4. 界面中文已确认：只能由学员亲眼检查菜单和主界面后回答。未确认时必须写“待学员确认”。

如果安装准备完成：
- 提醒学员先保存当前任务，再手动退出 Codex。
- Windows：让学员从桌面或开始菜单的“Codex 中文版”打开。
- macOS：让学员双击工具目录中的“macOS-打开中文版.command”；或在工具目录运行 /bin/bash "scripts/install_macos.sh" --action open。
- 请学员检查顶部菜单和主界面，并回答“都是中文 / 仍有英文 / 无法打开”。在收到回答前不要宣布最终成功。

第五步：遇到问题时排障
请先判断问题属于哪一类，并只做可恢复的处理：
A. 下载问题：检查官方 GitHub 地址、网络、磁盘空间、ZIP 是否完整，再重新下载到新的文件夹。
B. 官方 Codex 未找到：请学员先正确安装并至少打开一次官方 Codex；不要下载来历不明的 Codex 安装包。
C. 权限或安全校验问题：记录原始错误并停止。不要降低系统安全设置。
D. 空间不足：说明所需空间和当前可用空间，让学员自行选择其他安全位置或清理空间。
E. 官方 Codex 已升级：重新运行当前版本工具的安装检查；旧状态或旧副本不能直接视为有效。
F. 配置较复杂或状态记录损坏：优先使用工具自带的安全停止、备份、重装和状态检查；不要手工猜测修改 config.toml。
G. 启动后仍是英文：先运行状态检查，确认启动的是正确入口，再让学员提供界面现象。不要因为仍有英文就反复覆盖安装。

完成一次有依据的排障后仍失败，请判断为“疑似工具问题”或“尚无法判断”，停止继续改动，并进入第六步。

第六步：生成任务报告和助教反馈
先在聊天中给学员一份简短结果，再生成下面格式的“助教反馈正文”。只引用诊断报告里的版本、状态、失败阶段和关键错误，不粘贴完整私人配置或对话。

【学员结果】
- 当前结论：成功 / 安装准备完成但界面待确认 / 环境问题 / 疑似工具问题 / 尚无法判断
- 下一步：用一句话告诉学员应该做什么
- 是否改动官方程序：是 / 否 / 无法确认
- 是否保留备份：是 / 否 / 不适用

【助教反馈正文】
- 系统：Windows 或 macOS、具体版本、CPU 架构
- Codex：安装来源、程序版本、构建版本
- 汉化工具：仓库地址、指定版本或分支、实际提交 SHA、下载 ZIP 的 SHA-256
- 中文资源齐备：是 / 否 / 无法确认
- 安装准备完成：是 / 否
- 程序启动：未尝试 / 已发送启动请求 / 已检测到进程 / 启动失败
- 界面中文已确认：是 / 否 / 待学员确认
- 失败阶段：没有失败时写“无”
- 关键错误：只写必要错误摘要，隐藏用户名、邮箱、令牌和私人路径
- 已执行的排障：按顺序列出，最多列出必要步骤
- 问题判断：环境问题 / 疑似工具问题 / 尚无法判断
- 判断依据：说明为什么这样判断
- 建议维护者检查：指出可能需要更新的脚本、资源识别或教程，不要凭空断言
- 诊断报告位置：只给学员本机路径；如果路径含用户名，发送给助教前替换为 <用户目录>

如果“助教反馈方式”已经填写，先向学员展示脱敏后的反馈正文，并取得学员明确同意后再发送。如果没有可用的发送工具或学员没有同意，就不要假装已经回发；请让学员复制“助教反馈正文”交给老师。

【结束条件】
- 成功：安装准备完成，并且学员明确确认菜单和主界面中文。
- 部分完成：安装准备完成，但尚未退出重开或尚未人工确认界面。
- 失败：明确记录失败阶段、关键错误、已做排障和下一步，并生成可交给助教的脱敏反馈。
```

## 助教使用建议

- 发给学员前只需修改“指定版本或分支”和“助教反馈方式”两行。
- 正式发布后应使用版本标签，不要长期让学员跟随会变化的开发分支。
- 收到反馈后，先看“安装准备完成”和“界面中文已确认”，不要只看“脚本成功”或“进程存在”。
- 如需学员附加 JSON 报告或截图，应先提醒其检查用户名、邮箱、私人路径和通知内容。
