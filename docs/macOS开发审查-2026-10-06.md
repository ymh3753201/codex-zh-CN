# macOS 兼容汉化开发审查

当前为 `0.2.0-preview.1`，保持草稿，不合并、不正式发布。审查基线为 `517e678`，范围仅本次 macOS 兼容改动及相关测试、教程。

## 问题原因

官方中文设置只选择语言，不保证所有账号都加载主界面中文。只根据安装成功或进程存在宣布汉化成功不准确。静态发现远程开关，也不能证明账号实际开关已关闭。

## 修改内容

- 首次优先官方设置；已中文就不创建副本。本版本明确反馈仍英文，或点击「兼容汉化」后，才处理独立副本。
- 只使用官方内置中文资源。更新副本的资源及 Electron 内嵌校验值，保留完整性检查；不修改官方 App，不关闭系统安全保护。
- 复制后、首次写入前及签名前检查实际文件位置。拒绝越界符号链接和共享硬链接；写入函数自身也校验独立目标及来源哈希。
- 独立副本使用本地签名，不冒充 OpenAI 签名或新的 Apple 公证。系统拒绝启动就停止并报告。
- 不自动重启。官方仍运行时不启动共用对话目录的副本，不替用户关闭任务。恢复并明确重启时，先退出精确受管副本，再打开官方版本，不批量杀同名进程。
- 修改前备份，保留旧备份及失败副本。启动失败或中断会使副本失效，不能成为下次启动目标。官方升级后，旧版本的英文反馈失效。
- 报告分别记录资源、设置、安装准备、启动和本次人工中文确认；保留版本、失败阶段、日志位置及下一步，不包含密钥或完整对话。
- 提供双击入口、中文教程、工具包 SHA-256 和 Windows/macOS 通用 AI 提示词。学员无需安装额外运行环境。

## 测试结果

最终提交与 CI 链接在完成后补齐。此前检查点的成功不能代替最终提交的成功。

GitHub 执行原有 Windows 必需测试及发布包检查；macOS 执行 15 组基础回归、语言开关、独立副本、双架构 Mach-O、真实系统 codesign 合成夹具及解压包回归。覆盖首次/重复安装、损坏记录、缺文件、空间/复制/签名/写状态失败、特殊路径、升级、恢复、信号中断、越界链接、硬链接、直接写入保护及官方/无关数据不变。

合成签名夹具不包含真实 Codex 代码，不启动程序、不登录账号。Apple Silicon/Intel/Universal 文件结构模拟，不等于三种真实环境均已验收。

本机只修改源码、做静态检查和打包。用户要求停止后，没有再安装或启动本地测试副本。先前隔离测试数据已移至废纸篓，官方应用及正式配置前后哈希一致；详情见[真实测试范围和清理记录](macOS兼容副本实测-2026-10-06.md)。

### Standards（代码安全和仓库规则）

原 3 个阻断问题已修正：包内路径逃逸、直接调用写入函数缺少保护、启动中断未失效。硬链接测试缺口也已补。独立静态复审未发现新的阻断代码问题；自动回归是否通过以最终 CI 为准。

### Spec（是否满足任务要求）

原 2 个阻断行为已修正：默认直接准备副本、恢复时漏退出副本。持久英文反馈与后续状态建议不一致也已修正。仍有 1 项正式上线阻断：真实用户环境和完整界面验收未完成。

两条审查轴不混为一个“通过”：代码问题已修正，不代表产品已全面验收。

## 仍未验证的范围

- 真实远程翻译开关关闭账号的完整中文界面。
- 登录、已有任务、恢复英文后的实际界面，以及通知、电脑控制等权限功能。
- 真实 Intel Mac、其他 macOS/Codex 版本，尤其学员反馈的 `26.930.41038`（`13022`）。
- 带系统隔离属性、企业安全策略限制的机器；本地签名副本不是新公证应用，不能保证系统自动放行。
- 当前版本的真实 Windows 10/11 学员设备验收。Windows CI 通过不代替这些设备。

此前真实副本的有限验证范围：Apple Silicon、macOS `26.6.2`、Codex `26.930.51102`（`13100`）；资源/签名/普通启动及公开登录页面、菜单中文已观察，未登录、未检查已有任务。不能将这些观察写成完整主界面、灰度关闭账号或最终修改版本的实机验收。

结论：可提交供隔离测试的草稿预览，尚不能正式发布为「所有 macOS 下载即保证成功」版本。
