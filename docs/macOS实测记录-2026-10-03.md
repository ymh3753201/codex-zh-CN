# macOS 实测记录（2026-10-03）

补充更正（2026-10-04）：本记录中的 `installationReady=true` 是旧版只检查语言设置的历史结果，不能作为主界面翻译开关已开启的证据。`0.1.0-preview.3` 已加入门控检测；真实旧版 App 应报告设置已准备、门控值未知、汉化部分完成。详见 [语言开关反馈审查](macOS语言开关反馈审查-2026-10-04.md)。

## 问题原因

Windows 工具依赖 Windows Store 安装结构、PowerShell 和独立兼容副本，不能直接用于 macOS。macOS 当前官方应用名称可能是 `ChatGPT.app`，但包标识是 `com.openai.codex`；程序签名、Apple 公证、芯片架构和启动方式也需要使用 macOS 自带工具单独验证。

## 开发期间实际执行

- 对真实 `/Applications/ChatGPT.app` 执行只读资源、签名、公证、架构和进程检查。
- 使用带中文、空格、`&` 的临时 `CODEX_HOME`，对真实官方 App 完成安装、状态检查、两次启动请求和恢复英文。结果为 `resourcesReady=true`、`installationReady=true`、`programRunning=true`、`uiLanguageVerified=false`。
- 测试前后真实 `app.asar` 和正式 `~/.codex/config.toml` 的 SHA-256 均未变化；临时配置最终回读为 `localeOverride = "en-US"`。
- 自动回归使用伪造的最小应用结构和隔离配置，不读取账号、对话或私人配置内容。
- 为保护本次正在运行的 Codex 任务，没有退出正式应用，也没有修改正式 `~/.codex/config.toml`。两次启动测试复用了现有官方进程，因此只证明启动入口可用，不证明新窗口或中文界面已经验收。

## 上线前专业审查补充

- 修复了路径含 `|` 时临时文件清理范围不准确的问题，并加入“无关目录必须保留”测试。
- 修复了收到 `HUP`、`INT` 或 `TERM` 中断时可能未回滚的问题；现在会恢复配置和旧状态、返回失败，并生成中断报告。
- 对多行字符串、点分键、内联表等当前工具不能安全修改的复杂 TOML 写法明确停止，绝不猜测修改。
- 默认状态目录无法创建或日志无法写入时，改在权限为当前用户独享的临时目录生成问题报告。
- macOS 自动回归由 11 组增加到 15 组；发布包检查同时验证 `--help` 不得出现隐藏报错。
