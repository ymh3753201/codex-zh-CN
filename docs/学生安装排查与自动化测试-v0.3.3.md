# 学生安装失败排查与自动化测试报告

验证日期：2026-09-16。发布版本：v0.3.3。

## 结论

学生新截图的窗口标题和解压文件夹均显示 **v0.3.2**。该版本仍包含复制后递归遍历深层目录的旧代码，尚未包含 v0.3.3 的长路径修复。

本轮直接解压已发布的 v0.3.3 ZIP，使用正式安装脚本执行 12 组路径兼容测试，全部通过。在同一批复制结果上重放 v0.3.2 的原始遍历步骤，3 组成功、9 组失败。这验证了旧操作对电脑路径处理环境的依赖，能够解释“同一套工具，有的电脑成功，有的失败”。这不是学生实际失败率，也不是在 12 台电脑上测试。

截图与此缺陷发生在相同的深层依赖目录处理环节；由于未取得该学生完整的诊断报告，不能断言这是远端唯一原因。修复及本轮测试不要求修改注册表、管理员权限或安装 PowerShell 7。

## 修复内容与本轮审查

v0.3.3 已通过 Windows 自带的 Robocopy 在复制时处理目标文件的只读属性，取消了随后对整个依赖目录的 PowerShell 遍历。复制后仍会检查资源内容是否一致，再应用翻译补丁。

原始错误与清理错误分别保留，复制失败有独立日志。未完成的副本不会自动替代之前可用的安装。

本轮核对了压缩包和源文件，确认该修复确实包含在交付包中，并扩充了对照测试与失败场景测试。安装器版本继续保持 v0.3.3，交付 ZIP 与前次修复包一致。

## 测试范围

本机宿主为 Windows 构建 26100，Windows PowerShell 5.1.26100.9444。路径矩阵使用合成的最小 Codex 资源，执行真实的复制、补丁及安装逻辑；日常启动与进程操作由独立的真实应用测试覆盖。

真实程序测试使用 Codex Store `26.908.9136.0`。截图里的 `26.901.6511.0` 尚未取得完整安装包进行真实运行测试。本轮结果不等于所有 Windows 10/11 电脑或所有 Codex 版本均已验证。

## 给老师和学生的操作

1. 分发 `codex-zh-CN-v0.3.3.zip`，配合 `学生安装说明-v0.3.3.txt`。
2. 完整解压到新文件夹，双击该文件夹内的“一键安装.bat”。
3. 核对窗口顶部确实显示 **v0.3.3**。若显示 v0.3.2，仍然打开了旧入口。
4. 安装完成后使用“Codex 中文版”快捷方式。
5. 新版仍失败时，收集新文件夹 diagnostics 中的 JSON；如报告有 copyLog，同时收集该复制日志。不要仅根据截图猜测后续原因。

安装尚未完成的学生应运行“一键安装”，而不是仅更新启动器的“修复启动”。
