# v0.3.5 上线审查（2026-10-02）

结论：当前可以继续内部验收，不能正式上线。维护者明确确认，v0.3.5 尚未完成真实 Windows 10 和 Windows 11 的验收。本次更新保留在审查分支，不合并主分支，不创建正式 Release。

## 问题原因

1. 旧中文副本记录完整但 `app.asar` 被删除或无法读取时，重复安装会在核对文件阶段中止，无法自行重新准备副本。
2. CI 只生成 ZIP，没有执行现有发布包安装回归；两份含中文的测试脚本缺少 UTF-8 BOM。
3. 真实端到端脚本未核对 BAT 安装、状态命令和官方对照程序的全部退出码；界面检查可能接受没有语言的窗口，协议错误或截图缺失也未严格处理。
4. README 仍称英文系统不能测试中文快捷方式，发布信息仍指向原作者仓库。
5. 真实端到端工作流未提供 MSIX 地址，没有成功运行记录；旧 Codex 版本的成功记录不能替代本版实机验收。

## 修改内容

- 无法读取旧副本资源时重新准备并校验新副本，保留旧文件；新副本不会提前写入活动记录。
- CI 同时覆盖主分支和 `codex/` 分支，检查所有 PowerShell 文件的编码与语法，运行发布 ZIP 的源码哈希、安装、恢复、中文快捷方式和长路径回归。
- 公开标明 CI 跳过的真实 Codex 隔离用例，以及仅实机可检查的失败窗口按键等待。完整本地发布测试默认仍保留这些检查。
- 界面测试传播失败、要求有效语言和可见文字、要求截图，并限制每次协议请求等待时间。新增七种成功和失败判定测试。
- 修正仓库来源信息和过期说明，明确 v0.3.5 为待验收版本，保留原作者 MIT 许可。

## 测试结果

- 本地 macOS：全部 PowerShell 文件语法检查通过（PowerShell 7）；七种界面检查判定通过；发布 ZIP 全部 25 个文件与源码逐字节一致，PowerShell BOM 和 BAT/VBS CRLF 检查通过。
- 上次 Windows CI 对应旧提交 `d4f96e8`，[运行记录](https://github.com/ymh3753201/codex-zh-CN/actions/runs/36249249459)通过，但没有执行本次新增的发布 ZIP 回归。
- 本次 Windows PowerShell 5.1 测试以审查分支对应提交的 [GitHub Actions](https://github.com/ymh3753201/codex-zh-CN/actions/workflows/ci.yml) 记录为准，必须全部通过后才交付审查分支。
- 本次对公开前可达提交历史中的 144 个文本/二进制文件版本执行常见凭据模式检查，未发现匹配的令牌、私钥或带鉴权参数的下载链接。这是有限的模式扫描，不是对任意敏感信息的完整保证。公开前还应核对最终新增提交。

## 仍未验证的范围

- v0.3.5 在真实 Windows 10 22H2 / Windows 11 上的安装、重复启动、界面中文和恢复英文。
- 真实 Codex MSIX 的新一轮端到端测试；仓库没有设置 `CODEX_MSIX_URL`。GitHub Windows Server 不等于 Windows 10/11 客户端。
- 当前官方最新版是否仍匹配补丁结构；本次没有新的 MSIX 包。已有 26.917 离线审计不能扩展为未来版本保证。
- 所有页面、插件、账号状态和故障用户机器的现场表现。

## 正式上线前必须补齐

1. 按 [测试方案](测试方案-v0.3.5.md) 完成 Windows 10 和 Windows 11 至少两行实机验收，保存经过脱敏的状态报告和截图。
2. 提供可信 MSIX 下载地址，在隔离环境中运行真实安装包审计与端到端工作流。
3. 确认最终发布 ZIP，记录该文件的 SHA-256；本地打包与 CI 打包的 ZIP 时间信息可能不同，应以实际交付文件为准。
4. 上述证据齐备后再确认合并主分支和发布版本。
