# macOS 语言开关反馈审查（2026-10-04）

## 问题原因

反馈设备为 Codex `26.930.41038`（构建 `13022`）。用户已选择简体中文，但界面仍为英文；原报告把这认定为“工具正常、只怪上游”。这个结论过强：工具遗漏了主界面翻译加载前提，却把资源存在、语言写入和状态有效合并为 `installationReady=true`。这是工具本身的检测与兼容覆盖缺口。

本机为 Apple Silicon、macOS `26.6.2`、Codex `26.930.31730`（构建 `12947`），并不是反馈设备的版本。只读检查真实 ASAR 发现：

- `app-initial-576fc7ca620e.js` 主界面使用 layer `72216192` 的 `enable_i18n`，默认 false。
- `general-settings-68f5a30b13a9.js` 同一个参数默认 true。因此设置中能看到简体中文选项，不证明主界面会加载中文。
- 代码中的默认值只能证明存在这种失败路径，不能证明某个账号从服务端收到的真实值。新版报告将实际远程值保留为 `unknown`，不读取账号或私密缓存来猜测它。

## 修改内容

- `0.1.0-preview.3` 新增系统自带 JavaScript for Automation 只读检查器，无需安装 Node.js 或 Python。它按 ASAR 的准确位置读取中文词条和语言代码，校验字节范围、完整 SHA-256、分块 SHA-256，以及存在的 `ElectronAsarIntegrity` 文件头哈希。
- 独立报告 `settingsPrepared`、`languageGateDetected`、`languageGateStatus`、`remoteLanguageGateValue`。门控未验证或新版逻辑无法识别时，`installationReady=false`、`lastResult=partial`；未找到已知开关也不作为运行时已启用翻译的证据。原生模式仅在本次人工确认中文且安全前提通过后，才报告安装验收条件全部通过。
- `status --ui-result english` 记录当前人工验收失败，给出 `failureStage=ui-language-verification` 和疑似工具兼容缺口；不继续盲目重装或修改安全设置。
- `status --ui-result chinese` 仅在当前资源、签名、配置和状态有效时记录本次人工确认。以后普通状态检查不会冒充刚刚看过界面，也不会永久假设账号远程开关不变。
- 官方版本或构建号变化均使旧状态失效，即使 ASAR 字节未变化也必须重新检查。
- 若诊断报告生成失败，命令返回失败，不再只提醒后返回成功。

本次没有加入强制改 App 的副本补丁。修改副本资源后不能继续声称其原官方签名与公证有效；本地临时签名也不等于 Developer ID 和 Apple 公证。直接套用 Windows 补丁会引入另一个未验证的启动、登录和系统权限问题。参考 [Apple 公证要求](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。当前工具会如实留下未完成报告和恢复英文入口。

## 测试结果

- 修复前：`bash tests/test-macos-language-gate.sh` 在门控测试中失败，旧代码错误返回 `installationReady=true`。
- 修复后：覆盖远程门控、界面仍英文、中文人工确认、不复用历史界面结果、进程不代替验收、未知语言逻辑、中文文件字节损坏、构建号升级、官方资源与原配置不变，以及恢复英文。
- `bash tests/test-macos.sh`：原有 15 组安装、重复安装、缺文件、空间、备份、信号中断、恢复和架构分支测试继续通过。
- `node tests/test-macos-renderer-gate.mjs /Applications/ChatGPT.app/Contents/Resources/app.asar`：执行未修改的真实界面语言组件；相同 `localeOverride=zh-CN`，远程开关 false 时 messages 不加载，true 时加载。词条加载器和 React hooks 是受控测试替身，该结果不是界面中文验收，也没有修改上游开关或官方资源。
- 真实官方 App、隔离中文路径的数据目录：安装返回 `settingsPrepared=true`、`installationReady=false`、`languageGateStatus=remote-dependent`、`lastResult=partial`；恢复英文通过。前后正式配置和官方 ASAR 的 SHA-256 不变；`codesign --verify --deep --strict` 与 `spctl --assess --type execute` 通过。没有退出正在执行任务的官方 Codex，也没有伪造本机界面英文或中文的人工确认。
- 工具包校验及 GitHub Windows/macOS 测试链接在草稿 PR 中记录。

## 仍未验证的范围

- 用户反馈的 `26.930.41038`（构建 `13022`）没有在本机取得应用或运行日志，不能冒充复现该账号的实时开关。
- 尚不能为远程开关关闭的 macOS 用户自动确保显示中文。本次完成的是检测、报告、资源校验和验收流程修复，不是强制开启上游翻译。
- 真实菜单、主界面、登录、已有任务与恢复英文仍需人工验收；进程、截图或受控组件测试均不能替代。
- Intel Mac、其他 macOS/Codex 版本未实测。Windows 回归通过也不等于真实 Windows 10/11 学员机器全部通过。
- 当前仍为预览版草稿，不合并、不正式发布，不宣称已达到所有 macOS 学员可用的正式上线标准。
