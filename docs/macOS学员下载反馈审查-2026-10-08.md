# macOS 学员下载反馈审查（2026-10-08）

## 问题原因

学员环境：macOS 15.7.9、Intel Core i5-8259U / x86_64；Codex 26.1002.52244 / 构建 13536。报告下载的是 `main@69a9f16 / Windows v0.3.4`。远程默认分支确实仍是该提交，没有 macOS 安装入口；macOS 代码在未合并的草稿 PR #4。

因此，本次明确失败在**工具下载版本与平台入口检查**，尚未进入新版 macOS 安装流程。它暴露了我们的下载引导和交付问题。不能以此证明新版 Mac 代码失败，也不能归因为用户系统、芯片或官方翻译开关；同样不能说“完全与工具无关”。

学员的 `localeOverride=zh-CN`、系统语言和 `--lang=zh-CN` 只证明选择了中文语言环境。界面尚未由本人确认，结论只能是“官方设置已写入，工具未安装，界面待确认”，不是“汉化完成”。学员原始诊断文件及其哈希尚未独立取得，报告中的资源词条计数不冒充本项目实测。

## 修改内容

- macOS 预览工具升级为 `0.2.0-preview.2`。新增下载包预检，检查所有声明文件、必要运行依赖及版本一致性。缺文件或混用版本时，在读取官方程序和写配置之前停止，生成 `tool-package-check` 问题报告。
- 报告新增 `toolPackageReady`，与中文资源、语言设置、安装、启动和界面验收分别记录。
- 预检入口自身缺失、语法损坏、执行失败或输出无效时，安装器仍独立保存脱敏报告和关键日志，权限为 600；配置不修改，所有未检查的验收结果保持 false。
- 固定下载到完整源码快照 `03057f757d9722ff0228d4b73493bf0723110912`，不是默认 main。实际 ZIP SHA-256 为 `71492691fcba778fdcd2d28ad474ccbe3dbbe81fcedd2252c38a4dfa2ca90c78`。源码 ZIP 与独立 macOS ZIP 分别校验，不混用哈希。
- 排除源码 ZIP 内过期的维护者下载提示词；包内保留本地安装说明，根 README 使用有效网页链接。增加真实 HTTPS 下载回归，检查哈希、版本和跨平台入口，不只检查提示词文字。
- 打包与发布回归使用同一份文件清单；包内增加标明“汉化工具”的初读说明和适合本地文件的 AI 提示词。
- 保留官方设置优先、确认仍英文后使用独立副本的方案，不因发现语言开关就直接准备副本。
- 增加 `macos-15-intel` 测试环境，原 arm64 与 Windows 回归继续运行。Intel Runner 标签依据 [GitHub 官方说明](https://github.com/actions/runner-images/blob/main/README.md)。它验证工具运行环境，不等于学员机器实际界面验收。

## 测试证据

本机官方应用恰好同版：`/Applications/ChatGPT.app`，26.1002.52244 / 13536，arm64。仅只读检查，没有安装、复制、签名或启动真实应用/副本，没有修改真实用户配置。

- `codesign --verify --deep --strict /Applications/ChatGPT.app` 退出码为 0。
- 只读 `inspect-macos-asar.js` 返回 `resourcesReady=true`，ASAR 文件头 SHA-256 为 `b0d442ed63026a266e9f86df139bcafb9dcafe628b7065ea0473fe82760a82f0`。
- 主界面资产 `app-initial-61c077dcc1af.js` 与设置资产 `general-settings-5151ec63b051.js` 的预期语言开关都能识别。前者默认 false、后者默认 true；账号实际远程值仍是 unknown。不能据此推断学员账号一定未开放中文。
- 本地工具包预检回归通过：旧 Windows-only 包、缺少依赖、版本混用、异常文件清单、中文与特殊字符路径、失败时配置不变及报告不包含配置内容。
- 本地补充回归通过：预检脚本缺失、语法错误、执行失败、成功退出但无效输出时，均保存报告与日志，且不写配置、不创建用户状态目录。
- `tests/test-download-contract.py --archive <实际下载的源码 ZIP>` 校验固定版本及负面场景；学员不需要 Python，这是开发/CI 测试。
- 系统 `ditto -x -k` 实际解压固定源码 ZIP，中文及特殊路径、发布清单中的文件字节和包预检通过。终端旧版 unzip 本机出现中文名称乱码，因此提示词指定系统 ditto，CI 同样实际解压再预检；仅处理工具文件，不安装应用。
- 最终云端验证中，Intel macOS 15.7.9（24G830）的旧中断测试仅等待 2 秒，偶发在包/资源预检尚未完成时提前失败；同提交另一运行通过该步骤。改为最多 30 秒等待实际配置事务，进程提前退出立即报错并输出合成夹具日志。保留真实 TERM、配置回滚、无激活状态和问题报告的全部断言，不跳过或重试失败用例。
- 完整安装、资源/签名、复制、恢复、官方文件保护等回归在 GitHub Actions 执行，以 [PR #4 当前提交的 Checks](https://github.com/ymh3753201/codex-zh-CN/pull/4/checks) 为准。本地不进行真实应用安装测试。

## 独立审查结果

### Standards（代码安全与仓库规则）

预检入口自身缺失时没有持久报告的问题已修正，并有四类故障回归。最终源码复审未发现未解决的代码安全阻断；正式声明测试通过前，仍需核对当前提交的 GitHub CI。

### Spec（是否满足学员任务）

默认 main 下载错误平台、源码 ZIP 的说明断链、固定版本与校验值不一致的问题已闭环。实际下载的 `03057f7` 通过完整性及入口检查。未发现新增行为错误，但仍有一项正式上线验收阻断：真实 Intel 用户环境和完整中文界面未验收。两条审查轴不能合并成“全面上线通过”。

## 仍未验证的范围

- 学员原机 macOS 15.7.9 / Intel 的真实 Codex 签名、复制、启动、重开及中文界面。
- 新版 Codex 登录、已有任务、恢复英文和企业安全策略。
- 相同版本号不能证明 Intel 与 arm64 的程序文件字节完全相同；本机静态识别结果不能冒充 Intel 实机验收。

本轮保持预览和草稿状态。Windows 必需 CI 不得削减；本轮不合并、不正式发布，不改变仓库默认分支。
